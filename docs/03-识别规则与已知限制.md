# 识别规则与已知限制

> 双端共用同一套识别逻辑：安卓端内核与 Windows 端在 6 份测试文档上的 **452 条识别结果逐条 100% 一致**。
> 这一篇讲"它凭什么打、凭什么不打"，判断准不准时看这里。

---

## 1. 能识别什么

| 类型 | 覆盖写法 | 打码后 |
| --- | --- | --- |
| 手机号 | `13800138000`、`138****`、`+86 138…`、带分隔符的写法 | 整段覆盖 |
| 身份证号 | 18 位与 15 位，含校验位与国家/地区码校验 | 整段覆盖 |
| 银行卡号 | 16–19 位，做 Luhn 校验，避免把普通编号当卡号 | 整段覆盖 |
| 邮箱 | 常见邮箱格式 | 整段覆盖 |
| 座机号 | `区号-号码`、`区号 号码` | 整段覆盖 |
| 地址 | 省市区 + 街道门牌，含「XX 路 XX 号 XX 室」 | 整段覆盖 |
| 出生日期 | **只认带「出生 / 生日 / 生于」语义的日期** | 整段覆盖 |
| 性别 / 年龄 | `性别：女`、`…出生，女，今年 30 岁`、`李四，男，1990 年…` | 覆盖 |
| 姓名 | 保留姓氏，只遮名字：`陈嘉豪` → `陈██`、`欧阳志强` → `欧阳██` | 姓氏保留 |

### 什么绝不打

普通日期（会议、合同、签署、出差）、金额、车牌、快递单号、工号、型号、门牌里的数字等，一律原样保留。
号码类都先做校验（身份证校验位、银行卡 Luhn），干扰信息不会被误判。

## 2. 姓名怎么判断

这是最容易出问题的一类，规则写清楚：

1. **不依赖「姓名：」这类标签**。一段普通叙述里出现的人名也能认出来。
2. **只遮名、留姓**：两字名（李静）、三字名（黎新春）、复姓四字名（诸葛鸿明）都支持。
3. **拿不准的列成橙色「疑似」**，默认不打勾，你勾了才打。典型例子是人名后面直接跟名词——「李明辉团队」「谢天成工作室」，程序分不清是名字还是机构名。
4. **以「镇 / 苑 / 道 / 路 / 街 / 村 / 庄」结尾的会跳过**。这类字和地名无法区分，宁可漏掉也不误打正文。
5. **被换行拆成两半的姓名会漏**（姓在行尾、名在行首），按行处理时认不出。

## 3. 特殊版面怎么处理

| 场景 | 处理方式 |
| --- | --- |
| 多页 PDF | 逐页处理；界面顶部显示「X/Y 页有内容」，翻页处显示「本页 N 处」 |
| 一页多人 | 表格多行、一段话里出现好几个人，分别识别，不合并 |
| 表格相邻单元格 | 单元格之间没有分隔线、「手机号+身份证号」被连成一长串时，会在串内分段识别 |
| 表单类 PDF | 可以点进去填字的表单也会识别，字段值从文件里一并清除 |
| 出生日期被换行拆开 | 「1996 年 3 月 24 日出 // 生，女」这种也能认出 |
| 扫描件 / 拍照件 | 没有文字层的页会用**本机 OCR**（PP-OCRv4，离线运行）先认出文字与每字坐标，再套用同一套规则；界面会标出哪几页用了 OCR |

## 4. 马赛克是怎么做的（为什么不可还原）

不是画个黑块盖住，而是四步：

1. 把原文区域按像素重采样成小块，字形信息在采样时就被丢弃；
2. 向区域均色压平，再叠加随机扰动，像素与原文不再有对应关系；
3. **同时把这段的文本层删掉**——复制粘贴、搜索、提取文字都拿不到原文；
4. 另存为新的 PDF，文档属性（作者等）清空。

结论：打码后无法还原，也不能用工具"反马赛克"。

## 5. 已知限制（按影响排序）

| # | 限制 | 影响 | 怎么办 |
| --- | --- | --- | --- |
| 1 | 扫描件模糊 / 倾斜 / 字太小 | OCR 认错或漏认 | 核对识别结果，漏的用手动框选补；自动为空不代表没有隐私 |
| 2 | 加密 PDF | 打不开 | 先解除密码再导入 |
| 3 | 纯中文数字写的号码 | 不识别 | 手动框选 |
| 4 | 姓名以「镇/苑/道/路/街/村/庄」结尾 | 保守放过 | 手动框选 |
| 5 | 姓名或号码被换行拆开 | 可能漏 | 手动框选 |
| 6 | 拿不准的姓名只列「疑似」 | 默认不打码 | 在列表里手动勾上 |
| 7 | 手写体、艺术字 | 认不出 | 手动框选 |

## 6. 怎么自己验证准不准

仓库里带了一套可复现的测试文档与回归脚本（见 [05-构建与发布.md](05-构建与发布.md)「测试」）。要点：

- 6 份测试文档共 452 条隐私信息，双端识别结果逐条一致，坐标最大偏差 0.55pt；
- 纯净文档（不含隐私的正式公文）**0 误报**；
- 测试文档里的姓名、号码、地址全部是脚本随机生成的虚构数据，不对应任何真实的人。
