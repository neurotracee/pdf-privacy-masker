# 构建、测试与发布

> 面向想自己打包或发版的人。只想用的话看 [01](01-使用说明-Windows.md) / [02](02-使用说明-安卓.md)。
> 所有命令都在**仓库根目录**执行（安卓部分在 `android/` 下执行）。

---

## 1. Windows 端

### 1.1 环境

- Python 3.10 以上
- 依赖见 `requirements.txt`（PyMuPDF、Pillow、PyInstaller）

### 1.2 从源码运行

```bash
pip install -r requirements.txt
python pdfmask.py
```

### 1.3 打包成 exe

一键（推荐）：

```
双击 打包.bat
```

它会依次做：检查 Python → 装依赖 → 跑 `dev/sync_url.py` 同步项目地址到文档与 exe 属性 → PyInstaller 打包 → 打开 `dist/`。

手动等价命令：

```bash
pip install -r requirements.txt
python dev/sync_url.py
pyinstaller pdfmask.spec --noconfirm --clean
```

产物：`dist/PDF隐私打码工具.exe`，约 35 MB，单文件免安装。
exe 的文件属性（产品名、版本、版权）由 `version_info.txt` 决定，发版时改这里：`FileVersion` 与 `ProductVersion` 都要改。

### 1.4 命令行批量处理

```bash
python pdfmask.py --cli 输入.pdf 输出.pdf
```

打印一份 JSON，列出每处识别结果所在的页与坐标。

### 1.5 关键文件

| 文件 | 作用 |
| --- | --- |
| `pdfmask.py` | 主程序（后端 + 内嵌前端 HTML/CSS/JS 都在这一个文件里） |
| `version_info.txt` | exe 文件属性 |
| `app.ico` | 图标（用 `dev/make_icon.py` 生成） |
| `pdfmask.spec` | PyInstaller 配置 |
| `thanks_asset.py` | 赞赏码的 base64（单文件打包无法带外部图片，所以内嵌） |
| `打包.bat` | 一键打包 |

界面文案在 `pdfmask.py` 里：`DICT`（中文键 → 英文）、`PREFIX`、`TYPE_EN` / `STAT_EN`（类型与状态标签）。加新文案时**必须同时加到 DICT**，否则英文界面会漏。

## 2. 安卓端

### 2.1 环境

- JDK 17
- Android SDK（`compileSdk 34`、`build-tools 34`）
- Gradle 8.7
- 用 Android Studio 直接打开 `android/` 目录即可，或命令行 `gradle`

### 2.2 编译

```bash
cd android
gradle assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

### 2.3 签名

在 `android/` 下创建 `keystore.properties`（**不要提交到仓库**）：

```
storeFile=pdfmask-release.jks
storePassword=你的密码
keyAlias=你的别名
keyPassword=你的密码
```

- 没有 `keystore.properties` 时会退化成 debug 签名，只适合自己装来玩。
- `*.jks`、`keystore.properties`、`local.properties` 已在 `android/.gitignore` 里，别提交。
- 换签名会导致无法覆盖安装，**同一个 keystore 要一直留着**。

### 2.4 版本号

`android/app/build.gradle.kts`：

```kotlin
versionCode = 7        // 每次发版 +1，整数
versionName = "1.4.2"  // 显示给用户的版本号，要和 Windows 端一致
```

### 2.5 代码结构

```
android/app/src/main/java/com/neurotracee/pdfmask/
├── MainActivity.kt / App.kt       入口、导航、顶栏、各对话框接线
├── AppViewModel.kt                加载、识别、勾选、保存的编排
├── AppPrefs.kt                    语言 / 主题 / 保存目录（SharedPreferences）
├── Updater.kt                     检查更新（HttpURLConnection + org.json）
├── core/                          识别与打码内核（PDFBox-Android + PdfRenderer）
│   ├── Detector.kt                规则、姓名判定、跨行/列对齐
│   ├── PdfTextExtractor.kt        版面重建、字符框
│   ├── PdfMasker.kt               马赛克 + 抹除文字层 + 重排 PDF
│   └── Model.kt / Tables.kt / TextToken.kt
└── ui/                            Compose 界面
    ├── HomeScreen.kt / WorkScreen.kt   首页 / 处理页（含放大镜、双击取消、提示条）
    ├── SettingsDialog.kt               设置（语言、主题、保存位置、检查更新）
    ├── SaveTargetDialog.kt             首次保存询问
    ├── AppInfoDialog.kt                关于、赞赏码
    └── Lang.kt / Theme.kt / Fmt.kt     文案取值、主题、显示格式
```

改文案只动 `T("中文", "English")` 里的字符串；字号、间距用 dp/sp，密度自适应。

## 3. 测试

### 3.1 安卓

```bash
cd android
gradle testReleaseUnitTest   # 42 例：识别内核、更新解析、界面截图
gradle testDebugUnitTest     # 44 例：上面 42 例 + 2 例 Compose 控件测试
```

- `core/` 的单元测试用桌面版 PDFBox 验证识别结果与 Windows 端逐条对齐。
- `UpdaterTest` 覆盖检查更新的版本解析与比较（5 例）。
- `UiShotTest` 用 Robolectric 在 JVM 上真实渲染 Compose 界面，截图到 `app/build/ui-shots/`，覆盖竖屏 / 横屏 / 长屏 / 折叠屏 / 平板、中英双语、深浅两色、设置与关于面板、放大镜、更新结果卡片。用来核对排版有没有被挤坏。
- `ThanksQrLongPressTest`（仅 debug 变体）用真实控件长按赞赏码，验证长按确实触发保存、单击不触发。它需要 `ui-test-manifest` 里的 `ComponentActivity`，而那个依赖只链在 debug 上，所以 `app/build.gradle.kts` 里把 release 变体按包名排除了这个类。

当前：release 变体 **42 例**、debug 变体 **44 例**，均全通过。

### 3.2 Windows

`dev/` 下的脚本都不参与打包，只用来生成测试文档和跑回归。生成的 PDF 与截图写到 `test/`，已被 `.gitignore` 排除。

| 脚本 | 作用 |
| --- | --- |
| `make_test_pdf.py` | 生成基础测试文档：一张表里堆满各类隐私信息 |
| `make_hard_pdf.py` | 刁难文档 1.0：隐私信息与干扰信息混排 |
| `make_hard2_pdf.py` | 刁难文档 2.0：纯段落、零标签、虚构人物 |
| `make_hard25_pdf.py` | 刁难文档 2.5：5 页、每页多人多号码、含表格 |
| `make_hard3_pdf.py` | 刁难文档 3.0：5 页纯段落、零表格、三字名占多数 |
| `selfcheck.py` | 主自检：端到端跑一遍，核对每一类的召回与残留 |
| `test_hard3.py` / `test_hard25.py` / `test_hard2.py` | 按人物逐条核对姓名、号码、地址是否打掉 |
| `test_no_false_positive.py` | 纯净文档误报测试：不该打的地方一个都不能打 |
| `test_fp_extra.py` | 四种文体（说明文 / 技术规范 / 公文通知 / 新闻通报）的误报测试 |
| `blind_test.py` | 随机盲测：随机造名 + 随机句式，统计召回率 |
| `probe_names2.py` | 姓名识别探针：200 个两字名 + 200 个三字名 × 16 种句式 |
| `test_exe.py` / `smoke_exe.py` | 对打包后的 exe 做端到端冒烟测试 |
| `test_save_dir.py` | 保存位置接口：指定目录、自动建目录、写偏好文件、同名不覆盖 |
| `test_pickdir.py` / `test_pickdir_ok.py` | 系统原生「选择文件夹」对话框：能否弹出、取消、取回路径 |
| `make_ui_preview.py` | 把界面 HTML 注入假数据生成预览页，用于截图核对弹窗与勾选框 |
| `make_icon.py` | 生成 `app.ico` |
| `sync_url.py` | 改仓库地址后跑一次，把 `PROJECT_URL` 同步进所有文档与 `version_info.txt` |

示例：

```bash
python dev/make_hard3_pdf.py 2026      # 生成「刁难文档 3.0」
python dev/test_hard3.py 2026          # 校验识别与打码结果
python dev/test_hard3.py 2026 7 88231 5150   # 换种子，就是另一份文档
```

测试文档里的姓名、手机号、身份证号、地址全部由脚本随机拼出，不对应任何真实的人。

### 3.3 界面核对（Windows）

不用启动 GUI 也能看界面：

```bash
python dev/make_ui_preview.py          # 生成静态 HTML 预览（注入假数据）
```

再用 Edge headless 加 `--virtual-time-budget` 截图，比对设置面板、检查更新卡片、英文界面等。

## 4. 发布 Release

> 只想发版、不想看构建命令的，直接看 **[06-发布Release操作指南.md](06-发布Release操作指南.md)**（纯网页点击版，含自检与改错）。
> 本节讲的是发版之前的构建与命名规则。

### 4.1 附件命名（最重要）

「检查更新」是**从安装包文件名里读版本号**的，命名错了就会提示「已是最新」或「没有可用安装包」：

```
PDFPrivacyMasker-1.4.2.exe
PDFPrivacyMasker-1.4.2-arm64.apk
```

规则：`PDFPrivacyMasker-` + 版本号 + 平台标识（安卓补 `-arm64`）。不加空格、不写中文、不省略版本号。
读不到文件名里的版本时，会退回读 release 的 tag（形如 `v1.4.2`），所以 tag 也要规范。

### 4.2 发版清单

1. 改版本号：`pdfmask.py` 的 `VERSION`、`version_info.txt` 两处、`android/app/build.gradle.kts` 的 `versionCode` / `versionName`。两端版本号保持一致。
2. 在 `CHANGELOG.md` 顶部**新增一节**，写清新增功能与修复项（不要改旧节）。
3. 跑测试：`gradle testReleaseUnitTest` + `python dev/selfcheck.py`。
4. 打包：`打包.bat` 与 `gradle assembleRelease`，重命名产物成 4.1 的格式。
5. 建 Release：tag 用 `v1.4.2`，标题写版本号，正文直接摘 `CHANGELOG.md` 这一节。
6. 上传两个附件；顺手上传 `使用说明.txt`（可选）。
7. 发完自己点一次两端的「检查更新」，确认能读到新版本号。

### 4.3 AGPL 义务

分发 exe / apk 时必须同时提供能构建出该产物的完整源码（本仓库即是），并保留作者署名与原项目地址。见 [ADDITIONAL-TERMS.md](../ADDITIONAL-TERMS.md)、[NOTICE.md](../NOTICE.md)。

---

## 5. 改仓库地址时

只改 `pdfmask.py` 里的 `PROJECT_URL` 一行，然后：

```bash
python dev/sync_url.py
```

它会把本项目的地址同步到 `README.md`、`CHANGELOG.md`、`DOCS.md`、`NOTICE.md`、`ADDITIONAL-TERMS.md`、`使用说明.txt`、`version_info.txt` 以及 `docs/*.md`
（只替换本项目地址，不会碰 PyMuPDF / Pillow 等依赖的链接）。
